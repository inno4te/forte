Guided CLI labs

Step-by-step IOS practice.

Follow each lab in the CLI Simulator → or on real/emulated hardware. Each lab has objectives, a topology, step-by-step commands, and verification commands to confirm it worked correctly.

Tip: Open the CLI Simulator in a second tab alongside this guide. Type every command yourself — muscle memory matters in the exam lab sections. Use ? and Tab completion liberally.
🔧 Lab 1: Basic Router Configuration Beginner

Objectives

  • Set a hostname on a Cisco router
  • Configure IP addresses on two interfaces
  • Enable interfaces with no shutdown
  • Configure a default route to the ISP
  • Save the configuration to NVRAM
  • Verify with show ip interface brief and show ip route
Topology:
    [PC-A]─────[Gi0/0: R1 :Gi0/1]──────[ISP/Internet]
   192.168.1.0/24      203.0.113.0/30
   PC-A: 192.168.1.10   R1 Gi0/0: 192.168.1.1
   Gateway: 192.168.1.1  R1 Gi0/1: 203.0.113.2
                          ISP:      203.0.113.1
Step 1

Enter privileged EXEC mode and global config

Router interfaces are down by default. We start by setting the hostname.

Router> enable Router# configure terminal Enter configuration commands, one per line. End with CTRL/Z. Router(config)# hostname R1 R1(config)#
Step 2

Configure the LAN interface (Gi0/0)

This interface connects to the internal LAN. Assign it the gateway IP.

R1(config)# interface GigabitEthernet0/0 R1(config-if)# description LAN interface to 192.168.1.0/24 R1(config-if)# ip address 192.168.1.1 255.255.255.0 R1(config-if)# no shutdown R1: GigabitEthernet0/0 is up, line protocol is up R1(config-if)# exit
Step 3

Configure the WAN interface (Gi0/1)

The /30 subnet (4 addresses, 2 usable) is standard for point-to-point WAN links.

R1(config)# interface GigabitEthernet0/1 R1(config-if)# description WAN uplink to ISP R1(config-if)# ip address 203.0.113.2 255.255.255.252 R1(config-if)# no shutdown R1(config-if)# exit
Step 4

Add a default route pointing to the ISP

The quad-zero route 0.0.0.0 0.0.0.0 matches any destination not found in the routing table.

R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1 ! Alternatively use the exit interface: ip route 0.0.0.0 0.0.0.0 GigabitEthernet0/1
Step 5

Save the configuration

R1(config)# end R1# copy running-config startup-config Destination filename [startup-config]? [Enter] Building configuration... [OK]
✓ Verify

Verify your configuration

Run these commands and check the output:
R1# show ip interface brief Gi0/0 192.168.1.1 YES manual up up Gi0/1 203.0.113.2 YES manual up up R1# show ip route C 192.168.1.0/24 is directly connected, GigabitEthernet0/0 C 203.0.113.0/30 is directly connected, GigabitEthernet0/1 S* 0.0.0.0/0 [1/0] via 203.0.113.1
🔀 Lab 2: VLAN Configuration & Inter-VLAN Routing Beginner–Intermediate

Objectives

  • Create VLANs 10 (Sales) and 20 (IT) on a switch
  • Assign access ports to each VLAN
  • Configure a trunk port to the router
  • Configure router-on-a-stick (subinterfaces) for inter-VLAN routing
  • Verify hosts in different VLANs can reach each other via the router
Topology:
  [PC-Sales]─Gi0/1─[SW1 :Gi0/0 trunk]──Gi0/0──[R1]
  VLAN 10                                  Gi0/0.10: 192.168.10.1/24
  192.168.10.10/24                         Gi0/0.20: 192.168.20.1/24

  [PC-IT]────Gi0/2─[SW1]
  VLAN 20
  192.168.20.10/24
Step 1

Create VLANs on the switch

Switch> enable Switch# configure terminal Switch(config)# hostname SW1 SW1(config)# vlan 10 SW1(config-vlan)# name Sales SW1(config-vlan)# exit SW1(config)# vlan 20 SW1(config-vlan)# name IT SW1(config-vlan)# exit
Step 2

Assign access ports to VLANs

SW1(config)# interface GigabitEthernet0/1 SW1(config-if)# switchport mode access SW1(config-if)# switchport access vlan 10 SW1(config-if)# spanning-tree portfast SW1(config-if)# exit SW1(config)# interface GigabitEthernet0/2 SW1(config-if)# switchport mode access SW1(config-if)# switchport access vlan 20 SW1(config-if)# spanning-tree portfast SW1(config-if)# exit
Step 3

Configure the trunk port to the router

SW1(config)# interface GigabitEthernet0/0 SW1(config-if)# switchport trunk encapsulation dot1q SW1(config-if)# switchport mode trunk SW1(config-if)# switchport trunk native vlan 99 ! Change native VLAN from default 1 (security best practice) SW1(config-if)# exit SW1(config)# end SW1# show vlan brief
Step 4

Configure router subinterfaces (Router-on-a-stick)

R1(config)# interface GigabitEthernet0/0 R1(config-if)# no shutdown R1(config-if)# exit R1(config)# interface GigabitEthernet0/0.10 R1(config-subif)# encapsulation dot1q 10 R1(config-subif)# ip address 192.168.10.1 255.255.255.0 R1(config-subif)# exit R1(config)# interface GigabitEthernet0/0.20 R1(config-subif)# encapsulation dot1q 20 R1(config-subif)# ip address 192.168.20.1 255.255.255.0 R1(config-subif)# exit
✓ Verify

Verify inter-VLAN routing

Expected results:
R1# show ip interface brief Gi0/0 unassigned YES unset up up Gi0/0.10 192.168.10.1 YES manual up up Gi0/0.20 192.168.20.1 YES manual up up ! From PC-Sales (192.168.10.10), ping PC-IT (192.168.20.10): ! Traffic path: PC-Sales → SW1 (VLAN 10) → trunk → R1 → trunk → SW1 (VLAN 20) → PC-IT SW1# show vlan brief 10 Sales active Gi0/1 20 IT active Gi0/2
📡 Lab 3: OSPF Single-Area Configuration Intermediate

Objectives

  • Configure OSPF process 1 on two routers in Area 0
  • Advertise connected networks via OSPF network statements
  • Verify OSPF neighbour adjacency forms
  • Confirm routes are learned via OSPF (type O in routing table)
  • Understand OSPF DR/BDR election and router-ID
Topology:
  [LAN-A]                               [LAN-B]
  10.0.1.0/24                           10.0.2.0/24
      |                                     |
  [R1 Gi0/0]──────[Gi0/0:R1:Gi0/1]──────[R2 Gi0/0]──[Gi0/1:R2]
           10.0.12.0/30           10.0.12.0/30
           R1 Gi0/1: .1           R2 Gi0/0: .2
           R1 Gi0/0: 10.0.1.1    R2 Gi0/1: 10.0.2.1

Wait — cleaner:
  [R1]                [R2]
  Gi0/0: 10.0.1.1/24  Gi0/1: 10.0.2.1/24
  Gi0/1: 10.0.12.1/30 Gi0/0: 10.0.12.2/30
         ────────── link ───────────
Step 1

Configure R1 interfaces

R1(config)# interface GigabitEthernet0/0 R1(config-if)# ip address 10.0.1.1 255.255.255.0 R1(config-if)# no shutdown R1(config-if)# exit R1(config)# interface GigabitEthernet0/1 R1(config-if)# ip address 10.0.12.1 255.255.255.252 R1(config-if)# no shutdown R1(config-if)# exit
Step 2

Enable OSPF on R1 and advertise networks

R1(config)# router ospf 1 R1(config-router)# router-id 1.1.1.1 R1(config-router)# network 10.0.1.0 0.0.0.255 area 0 R1(config-router)# network 10.0.12.0 0.0.0.3 area 0 R1(config-router)# passive-interface GigabitEthernet0/0 ! Suppress OSPF Hellos on LAN — no other routers there R1(config-router)# exit
Step 3

Configure R2 (repeat for other router)

! On R2 — configure interfaces first, then OSPF R2(config)# interface GigabitEthernet0/0 R2(config-if)# ip address 10.0.12.2 255.255.255.252 R2(config-if)# no shutdown R2(config-if)# exit R2(config)# interface GigabitEthernet0/1 R2(config-if)# ip address 10.0.2.1 255.255.255.0 R2(config-if)# no shutdown R2(config-if)# exit R2(config)# router ospf 1 R2(config-router)# router-id 2.2.2.2 R2(config-router)# network 10.0.12.0 0.0.0.3 area 0 R2(config-router)# network 10.0.2.0 0.0.0.255 area 0 R2(config-router)# passive-interface GigabitEthernet0/1
✓ Verify

Verify OSPF adjacency and routes

Key verification commands:
R1# show ip ospf neighbor Neighbor ID Pri State Dead Time Address Interface 2.2.2.2 1 FULL/DR 00:00:38 10.0.12.2 Gi0/1 R1# show ip route ospf O 10.0.2.0/24 [110/2] via 10.0.12.2, 00:01:14, GigabitEthernet0/1 ! 'FULL' state = neighbours are fully adjacent and LSDBs are synchronised ✓ ! 'O' in routing table = OSPF-learned route ✓ ! Cost 110/2: reference 100Mbps ÷ 1Gbps = 1 per link → 2 hops = cost 2
🔒 Lab 4: Extended ACL — Traffic Filtering Intermediate

Objectives

  • Write an extended ACL to permit HTTP/HTTPS but deny Telnet from the LAN to servers
  • Permit ICMP so ping still works for troubleshooting
  • Apply the ACL on the correct interface and direction
  • Verify with show access-lists and test traffic
  • Understand the implicit deny any at the end of every ACL
Topology:
  [LAN: 192.168.1.0/24]──Gi0/0──[R1]──Gi0/1──[Server: 10.0.0.10]
  Goal: Allow HTTP (80), HTTPS (443), ICMP from LAN to Server.
        Deny Telnet (23) from LAN to Server.
        Deny all other traffic.
  ACL applied: Gi0/0 INBOUND (close to source = best practice for extended ACLs)
Step 1

Create the extended ACL

Extended ACLs use numbers 100–199 or a name. Named ACLs are easier to edit later.

R1(config)# ip access-list extended LAN-TO-SERVER R1(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 80 R1(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 443 R1(config-ext-nacl)# permit icmp 192.168.1.0 0.0.0.255 host 10.0.0.10 R1(config-ext-nacl)# deny tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 23 ! The line above is redundant because of implicit deny — but explicit is clearer ! Implicit: deny ip any any (invisible, always at the end) R1(config-ext-nacl)# exit
Step 2

Apply the ACL to the interface

Extended ACLs go close to the source. Apply inbound on the LAN-facing interface.

R1(config)# interface GigabitEthernet0/0 R1(config-if)# ip access-group LAN-TO-SERVER in R1(config-if)# exit
✓ Verify

Verify the ACL and hit counters

Verify ACL contents and match counts:
R1# show access-lists Extended IP access list LAN-TO-SERVER 10 permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 80 (5 matches) 20 permit tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 443 (2 matches) 30 permit icmp 192.168.1.0 0.0.0.255 host 10.0.0.10 (4 matches) 40 deny tcp 192.168.1.0 0.0.0.255 host 10.0.0.10 eq 23 (1 match) R1# show ip interface GigabitEthernet0/0 Inbound access list is LAN-TO-SERVER Outbound access list is not set ⚠ Remember: the implicit deny drops ALL traffic not explicitly permitted. ! Add 'permit ip any any' at the end if you want other traffic to flow.
🌐 Lab 5: PAT (NAT Overload) — Internet Access for a LAN Intermediate–Advanced

Objectives

  • Configure PAT (NAT Overload) to allow a private LAN to access the internet
  • Define inside and outside NAT interfaces
  • Create an ACL identifying which traffic should be NATted
  • Verify translations with show ip nat translations
  • Understand why PAT is used by billions of home/office routers worldwide
Topology:
  [LAN: 192.168.1.0/24]──Gi0/0──[R1]──Gi0/1──[Internet/ISP]
  Private addresses                  Public IP: 203.0.113.2
  192.168.1.x ─────────────────────────────→ 203.0.113.2:PORT#
  NAT translates MANY private IPs to ONE public IP using unique port numbers
Step 1

Define inside and outside interfaces

Every NAT config needs ip nat inside on the LAN interface and ip nat outside on the WAN interface.

R1(config)# interface GigabitEthernet0/0 R1(config-if)# ip nat inside R1(config-if)# exit R1(config)# interface GigabitEthernet0/1 R1(config-if)# ip nat outside R1(config-if)# exit
Step 2

Create an ACL identifying traffic to NAT

Only traffic matching this ACL will be translated. Typically the entire private subnet.

R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255 ! Standard ACL (1-99) — source IP only is sufficient for NAT selection
Step 3

Configure PAT (NAT Overload)

The overload keyword is what makes this PAT — one public IP, many private IPs.

R1(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload ! This tells IOS: translate source IPs matching ACL 1, using the public IP ! of Gi0/1, multiplexed by unique port numbers (PAT = Port Address Translation)
✓ Verify

Verify NAT translations

After a host sends traffic, check the NAT table:
R1# show ip nat translations Pro Inside global Inside local Outside local Outside global tcp 203.0.113.2:1024 192.168.1.10:2801 8.8.8.8:80 8.8.8.8:80 tcp 203.0.113.2:1025 192.168.1.20:3124 8.8.8.8:80 8.8.8.8:80 ! Both 192.168.1.10 and .20 share ONE public IP (203.0.113.2) ! Differentiated by unique port numbers: 1024, 1025, etc. R1# show ip nat statistics Total translations: 2 (0 static, 2 dynamic, 2 extended) Hits: 12 Misses: 0

📚 Lab practice strategy for exam success

For CCNA 200-301

  • Practice every lab until you can do it from memory — no notes
  • Understand the WHY behind each command, not just the syntax
  • Use show and debug commands constantly to verify
  • Practice subnetting until it's automatic (<30 seconds per problem)

For Network+ / Security+

  • Focus on concepts and protocols more than specific CLI syntax
  • Understand what each protocol does and what port it uses
  • For Security+: understand threat types, not just names
  • Read every explanation after each exam question — it's the curriculum
